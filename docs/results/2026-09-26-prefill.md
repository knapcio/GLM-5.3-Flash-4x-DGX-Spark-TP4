# Prefill measurements — LVKP-S-L2

**Benchmark:** `prefill-checked-client-first-observable-token`, measured 2026-09-26 on the four-Spark TP4 LVKP-S-L2 serving stack. This is prompt tokens divided by client latency to the first observable generated token, including scheduling, transport and first decode. It is not an isolated GPU-kernel throughput measurement.

| Actual prompt length | Median prompt tok/s | Median first-token latency |
|---|---:|---:|
| 16,705–16,708 tokens | **2,184.83** | 7.647 s |
| 33,574–33,577 tokens | **2,188.94** | 15.338 s |
| 67,304–67,309 tokens | **2,178.06** | 30.903 s |

Each row is the median of three requests at concurrency 1. Two initial requests at the nominal 32k size were warmups and excluded. Requested sizes were 16,384 / 32,768 / 65,536 tokens; the table uses the server's actual prompt-token usage. Rate and latency medians are calculated independently from the three samples.

The workload is deterministic generic numbered notes with a new leading nonce for each request. Every request asks for one output token, at temperature 0 and `reasoning_effort=low`. A role-only SSE chunk does not count as a generated token; the first nonempty content or reasoning delta establishes the timestamp. A complete response must report one completion token, consistent total usage, a terminal finish reason and `[DONE]`.

All 11 responses passed those checks. The independent audit reparsed retained wire bytes and timestamps, verified the complete fixed schedule and source hashes, and recomputed all nine scored rates and medians. Cache-token counters were absent in every response, so these are unique-prefix measurements, not a claim that reported cached-token counts were zero.

[Machine-readable samples and source hashes](2026-09-26-prefill.json) contain the two excluded warmups and nine scored observations. Endpoint addresses, nonce strings, prompt bodies and raw wire data are omitted from the public artifact; its source-record hash identifies the retained complete capture. This measures one generic workload and does not establish long-context quality or other prompt formats' prefill speed.

To repeat the fixed workload with no other requests running:

```sh
python3 -B -S bench/run_prefill.py --out prefill-new-run.json
```

The output path must be new. This runs two discarded warmups and three requests per size. The [runner](../../bench/run_prefill.py) and [SSE collector](../../bench/prefill_checked.py) are the exact measured sources; the collector uses Python's standard library.
